# Template Mutation(复制 → 最小修改)

> 正文规则:**模板优先于生成,复制优先于重写,局部替换优先于重新组织,原作者实际 Prompt 优先于 AI 总结出的规则。**
> 本文件定义"怎么改"。每一格默认操作是 **KEEP**。

## 0. 总流程

```
① 打开 template_XXX.json 完整原文(只读)
② deep copy(内存副本;禁止写回 template-library/)
③ 更新顶层 id / panel id(新 UUID)、title、seed
④ Character Replacement(§3)
⑤ Scene / User Delta(§4-5)
⑥ 若用户指定格数变化 → 阶段采样压缩/扩展(§6)
⑦ 三 Gate 验证(§7)
⑧ 输出新 JSON
```

索引(§1.2)只用于"找模板";进入本流程后一律读 `template-library/` 内部原文,把完整 prompt **原样保留**。

## 1. 面板级操作四种

每个面板只有四种操作,默认 KEEP:

| 操作 | 允许范围 | 禁止 |
|---|---|---|
| **KEEP** | 不任何修改 | — |
| **REPLACE** | 整块替换**身份相关块** / **场景相关块**(只换目标语义簇) | 换掉镜头/构图/剧情动作 |
| **PATCH** | 单块内部加点/改词(引用 tag-vocab.md 的词做最小补丁) | 重排顺序、改写语法 |
| **DELETE** | 删除确实与用户要求冲突的内容(如用户要求无群交 → 删除二男块) | 顺带清理"作者错拼/逗号/空格" |

禁止的三种重写:

```
"为了让 Prompt 更自然"  → 重写整格        (禁止)
"为了提升质量"          → 自己增加新 Tag   (禁止)
"为了统一"              → 清理作者标点/残位/重复(禁止)
```

## 2. 必须硬保留的原文资产

```
schemaVersion / JSON 字段布局 / panels 数组结构
panel 顺序 / 每格 prompt 基础文本
customCharacters[] 结构与空槽位 / paramsOverride 结构
imageSize 调度(每格画幅) / 镜头顺序 / 构图顺序
阶段长度 / Prompt 权重(N::tag:: 数值、0:: 残位、负权)
括号层级 / 重复 / 拼写漂移 / 特殊标点 / 作者原有短语与拼写
full prompt 的位序指纹(头部画质串 → 内容 → 尾句)
CC1 身份行写法 / 男块写法 / glom 防错写法
```

## 3. Character Replacement(人物替换)

### 3.1 身份替换(该换的)

```
title 中的角色名
prompt / CC 中的角色锚(official style, <角色名>, (Nth costume))
角色固有发色 / 眼睛 / 发型 / 体型 / 固有外貌特征
角色固有服装(默认服装词条;若用户给了新服装,按用户服装替换)
CC 内角色名引用的代词/昵称
```

识别方法:角色锚以 `official style, <name>` 为起点;固有外貌出现在 CC 内 `official style` 与第一个服装权重块之间;该模板 `template-index.json` 里的 `female_anchors` 给出锚名。

### 3.2 剧情状态(不换!)

下面这些属于模板剧情骨架,**不是角色属性,禁止误删**:

```
当前动作 / 当前姿势 / 当前镜头 / 构图 / 视角(POV/dutch angle)
当前场景状态 / 剧情阶段 / 当前互动 / 当前表情(哭泣/torogao/失神等剧情状态词)
状态变化顺序(服装只减不回穿的弧线)
男块(匿名男/教师/司机 → 换身份标签即可,动作块保持)
防错词(人物数量错误/多余角色/部位误入等)
```

### 3.3 角色属性 vs 剧情状态 判别表

| 词条 | 类别 | 操作 |
|---|---|---|
| `official style, nakano miku, 3::school uniform...` | 身份+固有服装 | 替换 |
| `3::school uniform, light blue sweater::` | 固有服装(若用户指定新服装) | 按用户服装替换 |
| `pantyhose, torn pantyhose` | 剧本服装状态(剧情链) | **保留**,除非用户明确要求改 |
| `headphone around neck` | 角色固有道具 | 替换/删除(若新角色无此物) |
| `park, bush, cardboard` | 场景状态 | 继承(KEEP),若换场景才处理(§4) |
| `from above, pov, cowboy shot` | 镜头 | **禁止替换** |
| `open mouth, crying, empty eyes` | 表情(剧情状态) | **禁止替换** |
| `man, boy, male blush` | 男块 | 保留写法;身份标签按 §3.1 |

### 3.4 服装与服装状态链分析(人物替换必做,语义审核)

> **脚本只能做"提取",不能做"替换判定"。** 作者把同一服装词分别用在正权块(穿)和负权块(除/防回穿),还伴随裸身状态词——裸扫 `pantyhose` 会把"已除"读成"回穿"。

#### 3.4.1 提取(工具辅助,事实层)

> 用 `tools/clothing_chain.py extract <template.json> --json` 提取(只搬原文,不做判断);
> `tools/clothing_chain.py verify <template.json> <mapped.json>` 做链校验(§7.4 用它)。

逐格扫描 CC0/CC1(及 prompt 服装块),按 P 序输出**状态时序表**:

| 档 | 区间 | 服装词(权重块原文) | 伴随身体状态词 |
|---|---|---|---|
| 完整 | P1-11 | `1.3:: pantyhose, green skirt::` | — |
| 撕裂 | P12-65 | `... torn pantyhose, green skirt::` | — |
| 过渡 | P66 | `-3::,torn pantyhose, green skirt::`(负数化) | — |
| 已除 | P67-82 | `bare legs ,  -2::pantyhose, green skirt::` | bare legs |
| 终局 | P83 | `bare legs, empty eyes, -4:: pantyhose, green skirt::` | bare legs |

#### 3.4.2 解读(LLM 语义判定,禁止脚本直接替换)

- **权重决定语义**:正权块 `N::word::` = 该服装**现行穿着**;负权块 `-N::word::` = 该服装**已被移除 + 防回穿**(不是回穿,不是无状态)。
- **断裂检测**:若裸扫出现"P12 torn → P67 完好",先判断是否为负数化过渡,不得下结论为回穿。
- **状态只减不回穿**:违反即说明解读错误,回 3.4.1 重读原文。

#### 3.4.3 映射(AI 定表,每档语义映射)

把用户角色服装档案逐档填入模板链(**位序/权重/括号/防回穿结构继承**,只更换时装词):

```
模板(裤袜链):   pantyhose(+1.3) → torn pantyhose(+0.3) → 已除(bare legs + -2::pantyhose) → -4:: p…
用户(黑裤袜):   black pantyhose(+1.3) → torn black pantyhose(+0.3) → 已除(bare legs + -2::black pantyhose) → -4:: b…
```

规则:
1. 每档换词 = 用户对应服装词(含状态前缀 torn/open/…),**权重值、括号、逗号残位、伴随词(bare legs/stylewords)一概不动**。
2. 用户服装与模板不同名(模板 `pantyhose` / 用户 `stockings`)→ 整链换名,状态机不破。
3. 模板独有而用户没有的服装(如 `sweater`)→ 默认继承(作者剧情用)并在报告标注;用户明确改了才替换。
4. 正权块与负权块**同词同换**(同一件衣服的穿/除两侧都用用户词)。
5. 用户角色多出的服装(如 `black pantyhose` 而模板无袜)→ 按 3.4.1 定插入槽位(身份块或对应服装块),不得自造新状态档。

#### 3.4.4 链校验(替换后必做)

```
✓ 状态变更格 = 模板同格(如 P12 撕裂、P67 已除,不得提前/延后)
✓ 只减不回穿;同格新旧不并存
✓ 防回穿负权随链换词(-2::-4:: 内含用户服装词,不得漏)
✓ 伴随身体状态词(裸腿/bare legs)留原样
```

### 3.5 Change Budget(改动预算)

```
普通角色替换:
  - 只改身份相关块   → 整卷 prompt 改动字符数预算 ≈ 身份词条占比(预估 ≤3-8%)
  - 禁止碰:镜头 / 构图 / 剧情动作 / 权重 / 括号 / 尾句
场景一致时:
  - 除身份块外,原 prompt 应几乎不变
场景替换时:
  - 只扩大到:身份块 + 场景块 + 依赖场景的动作/道具
```

## 4. Scene Replacement(场景替换)

### 4.1 只有用户明确要求换场景才做

- 模板场景 == 用户场景 → **场景内容尽可能不改**(KEEP)。
- 用户明确换场景 → 执行 Scene Mapping。

### 4.2 Scene Mapping(映射表先行)

先把**全部场景相关文案**找出来,列成映射表,再整套一致替换:

| 类别 | 换 |
|---|---|
| 地点 | 位置词(location/park/office/room/bed...) |
| 背景环境 | 环境块(树/窗/墙/道具/光线) |
| 时间 | 时间词(night/daytime/sunset)——按用户要求 |
| 场景道具 | 场景专属道具(篝火→花坛;纸板床→……) |
| 依赖场景的动作 | 如"野外被按在草地上"→"被按在办公室地板上";场景无关动作一律不动 |
| 场景相关镜头 | 如"从窗户射入的光"式构图词 |

| 类别 | **不换**(禁止动) |
|---|---|
| Panel 顺序 | — |
| 剧情推进 | — |
| 镜头节奏 | — |
| 角色状态变化顺序 | — |
| prompt 语法/权重/括号 | — |

示例(模板 park → 用户 gym):
```
park → gym / school gym
bush → storage racks / mats
cardboard → gym mat / bench
tree → wall / window
night 光线词 → 体育馆灯光词(按剧情时间)
```

### 4.3 全套一致(Scene Leak 反制)

必须追踪原模板中**全部** scene tokens / environment blocks / props / location descriptions / scene-dependent actions。
禁止出现:`P1=park / P12=bedroom / P30=room wall / P45=bed`(场景残留)。
做法:替换前先跑一遍词表扫描(`environment`/`important_props` 字段 + 全文 grep 地点词),列出命中清单,保证每个命中要么被映射、要么被显式保留。

## 5. User Explicit Delta(用户明确要求)

只有用户明确说才做:

```
群交 → 增加男块(从样本同题材找句法,不新创)
全裸收尾 → 修改终局服装状态(按模板已有全裸终局写法,如 7/31 套的 completely nude 写法)
道具(篝火/浴室/独木舟...) → 从 tag-vocab.md / samples 中找同样写法,拼入对应场景块
```

做 Delta 时参考顺序(§19 中文档仅为 Validator/Fallback):
1. 30 套真实模板里的同类写法(优先,逐字抄法);
2. `tag-vocab.md`(内容词库,用于最小补丁);
3. `style-guide.md` / `narrative-templates.md`(作者规律,仅校验,不作为生成源)。

## 6. 格数变化(用户指定格数才做)

```
用户无格数要求 → panel_count = Primary Template panel_count
  (例:模板 92 格 → 输出 92 格;模板格数 > 抽象统计默认值。禁止"默认 80 格就压成 80"。)

压缩(用户要 60,模板 82):
  ① 先标出模板的阶段(阶段识别:场景切换点/状态变化点/射精帧/事后模板帧)
  ② 按阶段等比例采样合并
  ③ 优先保留关键节点:首插/破处/射精帧/标点帧/终局
  ④ 删除冗余重复格(优先删过渡帧,保留双抽帧对至少 ≥4 对)

扩展(用户要 100,模板 82):
  ① 扩大阶段间隔:优先复制相邻格 + 最小 Delta(只改 L2,即表情/视线/焦点等小词)
  ② 禁止重新创造新剧情
```

## 7. 三道 Gate(交付前必检)

### 7.1 Anti-Rewrite Gate(禁止重写)

选定了 Primary 后,如果出现以下任一情形 → **判定失败,回滚**:

```
① 大量原权重消失(权重档位体系没保住)
② 大量原括号消失({{}} 层级密度骤降)
③ Prompt 顺序发生整体变化(位序指纹被重排)
④ 所有 panel 都变成 AI 自己的新语言(原文保留率骤降)
⑤ 镜头调度被重新安排(camera profile 与模板对应格不一致)
⑥ 出现原模板不存在的大量新句型(例如把 `::` 权重句改成 PIPE 或自然语言)
```

量化指标:**模板选中后,改动面板数 / 非身份块改动比例**。普通角色替换场景下,非身份文本保留率应 ≥90%;场景替换下 ≥80%。低于即回滚。

### 7.2 Identity Leak Gate(旧角色残留)

逐项检查,命中即改:

```
旧角色名                          ✗ 残留
旧发色                            ✗ 残留
旧眼睛                            ✗ 残留
旧专属服装                        ✗ 残留
旧身份道具(headphone/魔法帽/围巾等)✗ 残留(除非新角色保留)
```

**不得把以下误判成身份泄漏而删除**:剧情状态 / 镜头 / 动作结构 / 场景结构 / 服装状态弧线(如 torn pantyhose 链)——这些不是人物属性。

### 7.3 Scene Leak Gate(旧场景残留)

执行场景替换时检查:

```
原地名(park/office/inn...)          ✗ 残留
原环境物(tree/bed/floor 特定语境)   ✗ 残留
原家具/建筑特指词                    ✗ 残留
原场景专属道具(篝火/纸板床/铁丝网...)✗ 残留
```

只处理真正的 Scene Leak,不借此重写其他 Prompt。

### 7.4 服装状态链校验(人物替换时追加,见 §3.4.4)

```
✓ 状态变更格与模板同格 / 只减不回穿 / 同格新旧不并存
✓ 防回穿负权随链换词(-2::-4:: 块内已换用户服装词)
✓ 伴随身体状态词(bare legs 等)保持原样
```

## 8. 非法操作总表(红线)

```
✗ AI"优化作者":清理错拼/修正逗号/统一空格/统一括号/重排 Prompt
✗ 替换成更标准的 Danbooru Tag / 改成自然语言 / 重新组织权重
✗ 跨模板自动取长补短("T005 镜头更好,T021 权重更好"→ 禁止)
✗ 对模板学习后"重新创作"
```

Template Clone Mode 下:**作者原文就是标准答案。**
